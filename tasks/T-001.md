## Context

The user reports that Telegram "works", but `connections.json` shows `"connected": false` for all platforms.

**Manager's Initial Findings:**
- ✅ Token exists: `TELEGRAM_BOT_TOKEN` is configured in `.env`
- ❌ Connection state: `connections.json` shows `connected: false`
- ⚠️ Security: Current token is compromised (exposed in conversation)
- ⚠️ Dual state system: Two independent connection status implementations found

**Your Job**: Conduct a thorough read-only investigation to understand the architecture, identify the root cause of the connection state discrepancy, and document findings for implementation tasks.

---

## Goal

**Investigate and document the Telegram integration architecture, connection state management, and identify the root cause of the state discrepancy.**

This is **investigation-only**. Do NOT modify any application code.

## What to Investigate

### 1. Connection State Architecture (15 minutes)

**Trace both connection state systems:**

**System 1: In-Memory** (`server-new.js`)
- Location: Line 542-565 (Manager found this)
- How is `platformConnections.telegram` initialized?
- When is it updated?
- Which endpoints read from it?
- Which endpoints write to it?
- What happens on server restart?

**System 2: Persistent** (`connection-manager.js` + `connections.json`)
- How does `TelegramConnector` class work?
- When is `connections.json` updated?
- Which endpoints use the connection manager?
- What's stored in connection metadata?

**Key Questions:**
- Do these two systems synchronize? If so, where and how?
- Which system is the source of truth for the webhook handler?
- Which system is shown in the admin UI?
- What happens if they disagree?

### 2. Connection Flow (15 minutes)

**Trace the admin connection flow:**

1. User opens admin dashboard
2. User enters bot token
3. What API endpoint is called? (`/api/admin/telegram/connect`?)
4. What validation happens?
5. Which connection state(s) are updated?
6. Is the webhook registered automatically or manually?
7. What's returned to the UI?

**Inspect these endpoints:**
- `POST /api/admin/telegram/connect` (line 2271)
- `POST /api/admin/telegram/validate` (line 2333)
- `POST /api/admin/telegram/disconnect` (line 2420)
- `POST /api/telegram/set-webhook` (line 4328)

**Document:**
- Step-by-step flow with file:line references
- What gets updated where
- Any gaps or missing synchronization

### 3. Message Flow Architecture (15 minutes)

**Trace the complete message handling flow:**

```
Telegram User → Telegram API → ??? → Replai → AI → Replai → Telegram API → User
```

**Find and document:**
1. **Webhook reception**: Where is `POST /webhook/telegram` handled? (Manager found line 4638)
2. **Message parsing**: How is the message extracted from Telegram's webhook payload?
3. **User identification**: How is `userId` extracted?
4. **AI call**: Which function generates the response? `getAIResponse()`?
5. **Response sending**: How is the reply sent back? `sendResponseToPlatform()`?
6. **Logging**: Where are messages logged? Database? In-memory?
7. **Error handling**: What happens if AI call fails? If sending fails?

**Check the database:**
- Inspect `prisma/schema.prisma`
- Which models store Telegram data? (`Message`? `Session`? `Business.telegram`?)
- What fields are relevant?

### 4. Webhook Registration (10 minutes)

**Understand webhook setup:**

1. Find endpoint: `POST /api/telegram/set-webhook` (line 4328)
2. What does it do? Calls Telegram API `setWebhook`?
3. What URL is registered? Production? Localhost?
4. When is this called? Manual? Automatic?
5. Is there an endpoint to CHECK current webhook status? (`getWebhookInfo`?)

**Document:**
- How webhook registration works
- Whether it's verified after registration
- How to check if webhook is currently registered (if possible)

### 5. Root Cause Analysis (5 minutes)

**Based on your investigation, answer:**

1. **Why is `connections.json` showing `connected: false`?**
   - Was connection never established?
   - Was it disconnected?
   - Is state update missing somewhere?

2. **Why might user think Telegram "works"?**
   - Is in-memory state true while persistent is false?
   - Are messages actually flowing despite false state?
   - Is there an old/alternative code path?

3. **What's the actual current status?**
   - Can we verify from code inspection alone?
   - What would we need to verify live?

4. **What needs to be fixed?**
   - Synchronization issue?
   - Missing state update?
   - Webhook registration?
   - Something else?
