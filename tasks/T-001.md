## Context

The user reports that **Telegram "works"**, but `connections.json` shows `"connected": false` for all platforms including Telegram. We need to understand:

1. What does "works" mean? (code exists vs actual message flow)
2. Where is the connection-state discrepancy coming from?
3. What is the complete Telegram message flow architecture?
4. Is there a live Telegram bot actually receiving/sending messages?

**Security Note**: A Telegram bot token was previously exposed in conversation. Treat any token in `.env` or connections as potentially compromised. Never print token values.

---

## Goal

**Audit the Telegram integration end-to-end, trace its architecture, verify actual functionality with evidence, and document the connection-state discrepancy.**

This is an **investigation task**, not an implementation task. Your job is to understand what exists, what works, and what doesn't—backed by evidence.

## Investigation Stages

### Stage A: Architecture Trace (20 minutes)

**Map the complete Telegram message flow:**

1. **Incoming Messages**:
   - Webhook endpoint: `/webhook/telegram` (line ~6161)
   - What triggers it? (Telegram API webhook registration)
   - What does it do with messages? (parse, store, call AI?)
   - Where does conversation history live? (database models?)

2. **Outgoing Messages**:
   - How are replies sent? (direct Telegram API calls?)
   - What triggers a reply? (webhook handler, AI engine?)
   - Where is `botToken` used for sending?

3. **Connection Flow**:
   - How does admin connect Telegram? (UI → API → connection-manager?)
   - What happens on `/api/admin/telegram/connect`?
   - Does it update `connections.json`?
   - Does it set webhook with Telegram API?

4. **State Management**:
   - How does `server-new.js` line 543-545 relate to `connections.json`?
   - Why would `TELEGRAM_BOT_TOKEN` be in `.env` but connection show false?
   - Is there state stored elsewhere? (database? `businesses.json`?)

**Deliverable**: A clear markdown diagram of the message flow from:
```
Telegram User → Telegram API → Replai Webhook → Message Processing → AI Response → Telegram API → Telegram User
```

### Stage B: Code vs Reality Gap (20 minutes)

**Identify discrepancies between code and actual state:**

1. **Connection State Mystery**:
   - Inspect `connections.json` structure
   - Check if Telegram token exists in `.env`
   - Trace how `connection-manager.js` updates `connections.json`
   - Find why connection shows false despite token existence

2. **Webhook Registration**:
   - Check if `/api/telegram/set-webhook` (line 4328) was ever called
   - Does webhook URL point to production Render instance?
   - How to verify if Telegram is actually sending webhooks?

3. **Database Evidence**:
   - Check Prisma schema for Telegram-related models
   - Query database for any Telegram messages/conversations
   - Are there actual message records?

**Deliverable**: A list of evidence points:
- ✅ Token exists in `.env`: [YES/NO]
- ✅ Connection state in `connections.json`: [CONNECTED/DISCONNECTED]
- ✅ Webhook registered with Telegram: [UNKNOWN - requires verification]
- ✅ Message records in database: [YES/NO + count]
- ✅ Recent activity timestamp: [DATE or NONE]

### Stage C: Live Verification Requirements (20 minutes)

**Define what needs to be tested to prove Telegram works:**

1. **Connection Test**:
   - How to safely test with a new bot token (not compromised one)?
   - What API endpoint to call from admin UI?
   - Expected response and state changes?

2. **Message Flow Test**:
   - How to send test message to bot?
   - Where would it appear in logs/database?
   - How to verify AI response was sent back?

3. **Evidence Collection**:
   - What logs prove a message was received?
   - What database records prove conversation happened?
   - What Telegram API response proves bot is active?
