## Confirmed Scope (Based on T-001 Findings)

**T-001 Investigation Completed**: ✅  
**Root Cause Confirmed**: Dual-state synchronization issue

### Issue Summary from T-001

The system maintains two independent connection state systems:
- **In-memory**: `platformConnections.telegram` (server-new.js:542-565) - used by webhook handler
- **Persistent**: `connections.json` (connection-manager.js) - used by admin UI

**Current Problem**: These systems synchronize only during explicit connect/disconnect through admin UI. When tokens are added to `.env` manually or webhook is registered separately, states diverge.

**Impact**: `connections.json` shows `connected: false` while in-memory state (and message flow) works correctly.

---

### Priority 1: Fix Connection State Synchronization (15 minutes)

**Problem**: Disconnect and webhook registration endpoints don't update both states.

**Fix 1 - Disconnect Endpoint** (server-new.js:2420-2440):
```javascript
// CURRENT: Incomplete state clearing
platformConnections.telegram = { connected: false };

// SHOULD BE: Clear all fields
platformConnections.telegram = {
  connected: false,
  token: null,
  botUsername: null,
  botName: null
};
```

**Fix 2 - Webhook Registration** (server-new.js:4328-4347):
```javascript
// CURRENT: Only updates in-memory
if (data.ok) platformConnections.telegram = { connected: true, token };

// SHOULD ADD: Also update persistent state
if (data.ok) {
  platformConnections.telegram = { connected: true, token };
  const connector = connectionManager.getConnector('telegram');
  connector.updateConnectionState({
    connected: true,
    webhookUrl: webhookUrl,
    webhookRegisteredAt: new Date().toISOString()
  });
}
```

**Risk**: Low (additive changes, no breaking modifications)

### Priority 2: Add Admin-Friendly Webhook Status Endpoint (20 minutes)

**Problem**: Current webhook info endpoint exists but needs enhancement for admin dashboard.

**Current**: `GET /api/telegram/webhook-info` (line 3754-3761) - returns raw Telegram API response

**Add New**: `GET /api/admin/telegram/webhook-status` - returns admin-friendly format

**Implementation** (see T-001 report for full code):
- Checks if token configured
- Calls Telegram `getWebhookInfo` API
- Returns structured response:
  - `configured`: boolean
  - `webhook.registered`: boolean
  - `webhook.url`: string or null
  - `webhook.pendingUpdates`: number
  - `webhook.lastError`: string or null
  - `status`: 'active' | 'not_registered'
  - `message`: human-readable status

**Risk**: Low (new endpoint, no existing code changes)

**Problem**: Two endpoints return different connection states:
- `/api/admin/platform-status` (line 3697): Returns in-memory state
- `/api/admin/connections/all` (line 3673): Returns persistent state

**Fix**: Create new endpoint that shows BOTH states and highlights discrepancies.

**New Endpoint**: `GET /api/admin/telegram/status-debug`

**Returns**:

```json
    "connected": false,
    "connectedAt": null,

  },
  "synchronized": false,
  "discrepancies": ["connected status differs"],
  "webhook": {
    "registered": true,

  }
}
```

**Purpose**: Debugging and admin visibility into state synchronization issues.

**Risk**: Low (new endpoint, diagnostic only)

### Priority 4: Optional - Add Initialization Sync (5 minutes)

**Problem**: Server startup loads in-memory state from `.env` but doesn't check persistent state.

**Optional Fix**: On server startup, if in-memory loads `connected: true` but persistent shows `connected: false`, log a warning.

**Implementation** (after line 565):
```javascript
// After platformConnections initialization
const telegramConnection = loadConnectionStateFromFile('telegram');
if (platformConnections.telegram.connected && !telegramConnection?.connected) {
  console.warn('[Telegram] ⚠️  State desynchronization detected:');
  console.warn('[Telegram]     In-memory: connected=true (from .env)');
  console.warn('[Telegram]     Persistent: connected=false (from connections.json)');
  console.warn('[Telegram]     Consider reconnecting via admin UI to sync states');
}
```

**Purpose**: Alert operators to desynchronization on startup.

**Risk**: Very low (logging only, no state changes)
