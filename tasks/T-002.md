## Provisional Scope

Based on Manager's initial investigation, this task will likely address:

### 1. Connection State Synchronization

**Problem** (to be confirmed by T-001):
Two independent connection state systems exist:
- In-memory: `platformConnections.telegram` (server-new.js:542-565)
- Persistent: `connections.json` (managed by connection-manager.js)

These do not synchronize properly, causing state discrepancy.

**Proposed Fix**:
Ensure `/api/admin/telegram/connect` and `/api/admin/telegram/disconnect` endpoints update BOTH state systems atomically.

### 2. Webhook Status Verification

**Problem** (to be confirmed by T-001):
No way to verify if webhook is currently registered with Telegram API.

**Proposed Fix**:
Add new endpoint: `GET /api/telegram/webhook-info`
- Calls Telegram API: `https://api.telegram.org/bot<token>/getWebhookInfo`
- Returns: Current webhook URL, pending update count, last error
- Allows verification without manual Telegram API calls

**Option B**: Initialize in-memory from persistent on startup

**Option C**: Other approach recommended by T-001

### Stage B: Add Webhook Verification (20 minutes)

```javascript
app.get('/api/telegram/webhook-info', async (req, res) => {
  try {
    const token = platformConnections.telegram.token || process.env.TELEGRAM_BOT_TOKEN;
    if (!token) {
      return res.status(400).json({ error: 'Telegram not configured' });
    }

    const response = await fetch(`https://api.telegram.org/bot${token}/getWebhookInfo`);
    const data = await response.json();

    res.json(data);
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
});
```
